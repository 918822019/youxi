# 行军与军令

权威逻辑：`Game._route`、`Game._plan_order`、`Game._resolve_orders`（`backend/core/game.py`）。

## 军令类型

| 类型 | 含义 | 约束 |
|---|---|---|
| `move` | 调动到**本国**城池 | 目标必须属于自己 |
| `attack` | 进攻**敌国**城池 | 目标必须属于敌国；出发省须接入补给网 |
| `redirect` | 给行进中部队改令 | 部队须已有军令，且新目标不同 |
| `cancel_order` | 取消当前军令 | 立即生效，同日可重新下令 |

一支部队同时只能有一条军令；已有军令时须先 `cancel_order` 或 `redirect`。

## 路径与耗时

- 每个省份跨越需 **2 日**（`TRAVEL_DAYS`）。
- 寻路用 Dijkstra：`move` 只在己方省份间通行；`attack` 可途经己方省份，也可逐省攻入敌方控制区，**经过敌省权重为 4、己方为 1**，因此优先沿己方地区集结。
- 预计到达 `ETA = 路径省份数 × 2`；改令首段额外 +1 日。交战可能进一步延迟。

## 逐日结算

每推进一天，`_resolve_orders` 对每条军令：

1. 若目标或路线失效（不可达），记「路线被切断，军令已取消」并清除军令。
2. 若战线变化导致重算出的路线与当前路线不同，则**重新规划**并把本段计时重置为 2 日。
3. 计时 `daysRemaining` 减 1；未到 0 则本日结束。
4. 到 0 时进入下一省：
   - 到达**己方**省份：入城，日志「已抵达」，进行下一段（计时重置为 2）。
   - 到达**敌方**省份：进行[战斗结算](combat.md)。
5. 抵达最终目标后清除军令。

!!! note "交战改变 ETA"
    改令、重规划与战斗胜负都会改变实际到达时间，面板显示的预计到达只是当前估计。
